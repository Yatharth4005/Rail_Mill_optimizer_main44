Dynamic Fallback Hierarchy

When the system generates a plan for a selected profile section, it executes a hierarchical rule resolution engine:

  1. Specific Weight Map Match: Queries the SectionWeightMap database table for a match on Section Name + Finished Section Weight. If matched, resolved casting specs, tolerance, and location rules are applied.
  2. Default Section Fallback: If specific weight is not found, queries the SectionRule database table to fallback to general specifications of the section.
  3. Hardcoded Plant Defaults: If no rule exists in the database, falls back to default plant properties (10.00m length, 0/40 tolerance, MCAP location, raising a warning notification).
Note: Changes to formula variables apply globally across the rolling plan generation and must be validated before production deployment.
